1. Introduction

Screen Monk is a privacy-first, local-only screen-time and digital wellbeing application for Windows. The application is built around a single principle: a quiet record of your hours, kept on your own machine, shared with no one.

This Privacy Policy describes the information Screen Monk processes, where that information lives, what Screen Monk does with it (and does not do with it), and the controls you have over it. It applies to the Screen Monk desktop application for Windows and to the Screen Monk website at screenmonk.app.

This is one universal policy. The same document is linked from the Screen Monk website and is provided as the official Privacy Policy for the Windows application, including for submission to the Microsoft Store.

2. Information Screen Monk Processes

Screen Monk processes the following categories of information. All of it is generated by the application running locally on your computer, from signals already available to a program running on your own machine.

Active application and window information

The name of the foreground process (for example, the executable that produced the active window), the title of the active window, and the time at which focus changed. This is the core signal Screen Monk needs to know which application you are using.

Application and process information

The display name and file path of each distinct executable Screen Monk observes, a category you (or Screen Monk's default rules) assign to it, and an optional icon extracted from the executable. This lets Screen Monk show you a recognisable list of apps instead of a list of process names.

Usage duration

The amount of time each application was in the foreground. Screen Monk records one continuous span per (application, window title) pair, and rolls these spans up into per-day and per-hour summaries for the dashboard.

Idle and active state

Whether you are at the keyboard, derived from the Windows GetLastInputInfo API. Idle periods are recorded so Screen Monk can distinguish time you were away from your machine from time you spent using it, and so it can suppress reminders while you are already away.

System power and lock events

Whether the computer went to sleep, woke up, locked, or unlocked. Screen Monk uses these as hard boundaries on tracking so that suspended or locked time is never counted as active use.

Browser website visits (best-effort)

For common browsers, Screen Monk extracts the website domain from the active window title. Only the domain is stored; the full page title, query string, and any other URL parameters are not stored. Visits for which no domain can be reliably detected are not recorded at all.

Focus sessions, limits, and goals

If you use the Focus feature, Screen Monk records the start time, intended duration, allow-list of apps or domains, and any distractions (apps you opened during a focus session). If you set a daily or weekly limit on an application, the limit and the mode (soft reminder or hard block) are stored alongside the app record.

Categories, rules, and presets

Custom categories you create, title-pattern rules you define for automatic categorisation, and focus presets you save. All are stored locally so Screen Monk can apply them the next time you use the application.

User-configured settings

Preferences you set inside the app: privacy mode, break reminder interval, launch at startup, run-in-tray, retention period, the path to your chosen Vault, the position of any floating widget windows, and similar options. These live in a small JSON configuration file in the application's user data directory.

Local application logs

A short rolling log of application lifecycle events (start, stop, errors) and boot diagnostics, written to a file inside your Vault. These exist so the application can diagnose problems on your own machine; they are not transmitted.

What Screen Monk does not collect

Screen Monk does not collect your name, email address, phone number, account credentials, IP address, device identifiers, precise location, contacts, calendar entries, photographs, microphone or camera input, biometric data, or any other personal information that is not generated by the application itself while running on your machine.

3. How Screen Monk Uses Information

Information processed by Screen Monk is used only to provide the application's features to you, on your machine. Concrete uses include:

  • Recording screen-time by application, window title, and website domain.
  • Displaying daily, weekly, and monthly summaries on the dashboard and Analytics view.
  • Computing per-hour and per-day timelines and "top apps" lists.
  • Categorising applications and websites into the categories you (or the default rules) assign.
  • Tracking Focus sessions, recording distractions against the session's allow-list, and storing the resulting session record.
  • Enforcing daily and weekly application limits and surfacing reminders or blocks when a limit is reached.
  • Issuing break reminders when you have been active for a sustained period, and suppressing them when you are already away from the keyboard.
  • Displaying floating widgets you have enabled (for example, a clock or current app), positioned where you placed them.
  • Building a recognisable icon for each application from the executable, so the dashboard is readable.
  • Producing exports you explicitly request (CSV, JSON, or a backup of your Vault), saved to a location you choose.
  • Applying the data retention policy you have configured, by pruning old activity records after the retention window has passed.

Screen Monk does not use the information it processes for advertising, profiling, audience segmentation, credit scoring, employment decisions, or any other purpose outside the application's own functionality.

4. Local Storage and the Vault

Screen Monk stores the information it processes on your computer, in a directory called the Vault. The Vault is a normal folder; you can open it in Windows Explorer and inspect its contents at any time.

You choose where the Vault lives. The application prompts you to pick a location during onboarding, remembers that choice, and uses it on every subsequent launch. The default location, if you do not pick one yourself, is a folder inside the application's user data directory. You can move the Vault to a different drive, an external drive, or a cloud-synced folder at any time; doing so is a deliberate choice on your part, not something Screen Monk initiates.

Inside the Vault, Screen Monk writes:

  • A SQLite database file (managed by the open-source better-sqlite3 library) holding all activity, idle, focus, app, limit, category, rule, and summary records.
  • A folder of cached application icons extracted from the executables you have used.
  • An Exports folder containing any exports you choose to generate.
  • A Logs folder containing a short, rolling application log.
  • A small .screenmonk-vault marker file that identifies the folder as a Screen Monk Vault and stores its name and creation time.

In addition to the Vault, Screen Monk writes a small config.json file in its user data directory (managed by the open-source electron-store library). This file holds preferences such as the path to the current Vault, the position of any widget windows, and whether the application should launch at startup. It does not hold your activity history.

Screen Monk does not upload the contents of the Vault or the configuration file to Screen Monk's servers, to any third party, or to any cloud service. There is no automatic cloud sync, no scheduled backup to a remote endpoint, and no remote mirroring of any kind. If you want your Vault to be backed up off this machine, you must arrange that yourself (for example, by placing the Vault inside a folder that your own cloud-storage client already syncs).

5. Network Communications and Telemetry

Screen Monk does not contain analytics, telemetry, crash reporting, error reporting, product usage tracking, advertising, or automatic update services. The application has no account system and no remote API of its own.

In normal use, the application does not initiate any outbound network connection. The renderer process runs under a Content Security Policy that restricts connections to the application's own resources, which means third-party services cannot be reached from the user interface even if a future bug were to attempt it.

The single exception worth naming is one optional image resource in the application's source code that would, if reachable, request a website favicon from a third-party service to display next to website-domain entries on the Browser activity screen. In the released application, this request is blocked by the renderer's Content Security Policy, and the screen instead shows a small placeholder. The request is therefore not made during normal use.

The application may also open an external link in your default web browser when you click a clickable link inside the application. This is initiated by you, the user, and only the URL you clicked is passed to the operating system to be opened in your browser of choice. Screen Monk does not observe or record this action.

The Screen Monk website at screenmonk.app uses Google Fonts to serve the site's typography. No other third-party requests are made by the website: no analytics scripts, no advertising networks, no tracking pixels, and no social-media embeds. The website's Content Security Policy is published as a defense-in-depth measure to make this a hard guarantee, not a soft one.

6. Data Sharing and Disclosure

Screen Monk does not sell, rent, lease, or trade any information it processes. Screen Monk does not share your information with advertisers, analytics providers, data brokers, social networks, payment processors, marketing platforms, or any other external party.

Because the information Screen Monk processes never leaves your machine, Screen Monk has no information to disclose to third parties, law enforcement, or other requesters. If a third party seeks information about you, Screen Monk cannot produce it, because Screen Monk does not hold it.

Screen Monk will only disclose information it actually holds in narrow, legally compelled circumstances — for example, a valid court order directed at Screen Monk itself. In such a case, the response would be limited to the information in Screen Monk's own possession (which is none of your screen-time data, because that data is held by you, on your machine, not by Screen Monk).

If Screen Monk is ever acquired or transfers its assets, any information in Screen Monk's own possession would transfer to the acquirer under the terms of this policy. Again, because the substantive data lives in your Vault and not with Screen Monk, this transfer is, by design, of limited practical consequence.

7. Third-Party Components

The Screen Monk application uses a small number of open-source software libraries, each chosen for running locally on your machine. These libraries are not "data recipients" in any privacy sense: they execute code inside the application, on your computer, and do not contact external services on your behalf.

  • Electron — the application runtime that hosts the user interface.
  • React — the user-interface library used to render the dashboard.
  • better-sqlite3 — a local SQLite library used to read and write the Vault database. No network activity.
  • electron-store — a small JSON configuration store for application preferences. No network activity.
  • koffi — a foreign-function interface used to call a small number of Windows system APIs (idle time, foreground window). No network activity.

The Screen Monk website uses Google Fonts to load the site's typography. The request to Google Fonts reveals your IP address and User-Agent to Google in the ordinary way that any web request does; this is the only request the website makes to any external service.

Screen Monk is not a data joint controller or processor on behalf of any of the above. They are not given access to your screen-time data, your Vault, or any other personal information processed by Screen Monk.

8. User Control

Because your data lives on your machine, you have direct and complete control over it. The following controls are available to you.

Viewing your data

The application's dashboard, Apps view, Browser view, Categories view, Timeline, and Analytics view let you browse the data Screen Monk has recorded. You can also open the Vault folder in Windows Explorer and inspect the underlying SQLite database directly.

Exporting your data

The Vault screen lets you export your activity data as CSV or JSON, and lets you create a local backup archive of the entire Vault. Exports and backups are written to a location you choose; they are not transmitted by Screen Monk.

Deleting your data

You can delete individual records from inside the application, clear all data for a specific application, delete categories, rules, or focus presets, or delete the entire Vault from the Vault screen. Deleting the Vault folder is a normal folder delete in Windows Explorer and is a permanent and complete way to remove all of your screen-time data.

Privacy Mode and per-app overrides

A global Privacy Mode in Settings masks window titles throughout the application. You can also set a per-app privacy override so the titles for a specific app are masked even when Privacy Mode is off. With Privacy Mode enabled, Screen Monk still records which app you used and for how long, but does not record the window title.

Retention

Settings includes a retention option. When enabled, Screen Monk prunes activity records older than the configured retention window once per day.

Uninstalling Screen Monk

The Windows uninstaller removes the application and the default user data directory. The Vault folder you chose is not touched by the uninstaller; if you also want to remove the Vault, delete the Vault folder yourself before or after uninstalling.

9. Security

Screen Monk is designed so that the most sensitive data it holds — your screen-time history — lives on your computer, under your control, and is not transmitted to anyone. Beyond that baseline, the application applies a number of reasonable safeguards:

  • The renderer process runs under a strict Content Security Policy that limits outbound network requests to the application's own resources.
  • Configuration and database files include corrupt-file recovery so that a partial write cannot render the application unusable.
  • A single-instance lock prevents the application from being launched in two windows at once, which would otherwise race on the same database file.
  • Application lifecycle errors are logged locally; the application surfaces a clear error message rather than failing silently.
  • Updates to Screen Monk are delivered through the official installer you downloaded; the application does not silently self-update from a remote endpoint.

No security design is perfect. Screen Monk does not promise that the information on your machine is immune to every possible attack. In particular, if your computer itself is compromised, or if another user with access to your computer opens the Vault, the contents of the Vault can be read. Standard operating-system-level security practices — keeping your operating system up to date, using full-disk encryption where appropriate, limiting who has access to your machine, and so on — remain the foundation on which Screen Monk's local-only design rests.

10. Children's Privacy

Screen Monk is a general-purpose productivity and digital-wellbeing application for Windows. It is not specifically designed for, and is not directed to, children under the age of 13. Screen Monk does not knowingly collect personal information from children, and because the application does not collect personal information from anyone, the distinction is largely academic in practice: the data Screen Monk processes comes from the computer the application is installed on, not from any identified person.

If you are a parent or guardian and have questions about Screen Monk's use on a child's computer, please contact Screen Monk using the details in Section 12.

11. Changes to This Privacy Policy

Screen Monk may update this Privacy Policy from time to time, for example when the application's behaviour changes, when a new feature is added that processes a new category of information, or when legal or regulatory requirements change. The "Effective" date at the top of this page records when the current version came into effect.

When this policy changes in a way that materially affects what information Screen Monk processes or how it is handled, the change will also be announced inside the application on next launch. Continued use of Screen Monk after the effective date of an updated policy indicates acceptance of the updated policy.
